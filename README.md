## 🎯 Website Goals

The OVEQIRA website is designed around four core objectives:

### 01 — Clarity

Visitors should quickly understand what OVEQIRA does and how we can help.

### 02 — Credibility

Real client projects and verified work take priority over artificial social proof.

Every major page provides a clear next step for potential clients.

### 04 — Experience

---

## ✦ Design Direction

The website follows a **minimal, premium, light-theme design system**.

### Visual principles

* Clean typography
* Generous whitespace
* Strong hierarchy
* Editorial layouts
* Restrained accent color
* Subtle borders
* Minimal shadows
* Purposeful animation
* Responsive layouts
* Accessible interactions

The design deliberately avoids:

* Excessive gradients
* Heavy glassmorphism
* Neon effects
* Unnecessary animation
* Generic stock imagery
* Overloaded interfaces
* Fake dashboards
* Artificial social proof

The premium character of the website comes from **clarity, composition, typography, and restraint**.

# 🏗️ Architecture

The project follows a modular, data-driven architecture.

The goal is to keep **content separate from presentation**, making the website easier to maintain and expand.

Conceptually:

```text
User
 │
 ▼
React Application
 │
 ├── Pages
 │
 ├── Layouts
 │
 ├── Components
 │
 ├── Data
 │
 ├── Styles
 │
 └── Utilities
```

Content such as services, projects, testimonials, navigation, FAQs, and site configuration is maintained separately from reusable UI components wherever possible.

# 🚀 Deployment

The OVEQIRA website is designed for deployment on **Netlify**.

Production build configuration:

```toml
[build]
  command = "npm run build"
  publish = "dist"
```

For a client-side React/Vite application, SPA routing should also use a Netlify fallback:

```toml
[[redirects]]
  from = "/*"
  to = "/index.html"
  status = 200
```

The final `netlify.toml` should remain compatible with the application's actual routing implementation.

# 🔐 Environment Variables

Never commit secrets to GitHub.

If environment variables are required, create a local:

```text
.env
```

file.

For Vite client-side variables:

```text
VITE_*
```

may be used where appropriate.

Remember that variables exposed to browser-side code are **not secret**.

Never place:

* API secrets
* passwords
* private tokens
* authentication credentials

inside frontend source code.

# 📚 Adding a New Service

To add a service:

1. Add the service to `src/data/services.ts`
2. Define its slug
3. Add the required content
4. Connect it to the reusable service page
5. Add related projects where applicable
6. Add SEO metadata
7. Verify navigation
8. Test the service route
9. Run the production build

The UI should not need to be rewritten for every new service.

---

# 💼 Adding a New Project

To add a project:

1. Add the project to `src/data/projects.ts`
2. Assign a unique ID
3. Add a unique slug
4. Add verified client information
5. Add delivered services
6. Add genuine project images
7. Add case-study information where available
8. Connect related services
9. Add approved testimonial only if available
10. Verify `/work`
11. Verify the project detail route
12. Run the production build

Never add fictional portfolio projects.

# 🎨 Design System Principles

The OVEQIRA interface follows several design principles.

### 01 — Less, But Better

Every element should have a reason to exist.

### 02 — Typography First

Strong typography creates hierarchy before decoration is introduced.

### 03 — Whitespace Is a Feature

Give content room to breathe.

### 04 — Interaction Should Feel Natural

Animations should explain or reinforce interaction rather than distract from it.

### 05 — Consistency Builds Trust

Buttons, spacing, typography, colors, cards, and navigation should behave consistently.

### 06 — Real Work Over Artificial Proof

The portfolio should represent genuine work rather than manufactured credibility.
